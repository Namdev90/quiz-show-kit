# Quiz Show Kit v1.1.0

The current prompt-led toolkit, updated BioVista feature showcase and editable-bank workflow are now delivered together. This supersedes v1.0.0's retired browser-builder package; historical releases and the original BioVista archive remain available for reference.

## Start here

- Download `Quiz_Show_Kit_v1.1.0.zip`, extract it and open `quiz-show-kit/index.html` for the current launch prompt. Its first unresolved setup question offers **Teacher mode** (automatic presets and essential questions) or **Competition mode** (granular supported controls).
- Open `BioVista_Quiz_Public_Example.html` directly for the self-contained current example. No Node, Python, server or API key is needed to play it.
- The ZIP includes editable configurations, the DOCX bank, reusable settings, quality review, feature tour, source, tests, licenses and historical archive. Keep the DOCX with its matching showcase configuration when importing edits.
- Verify downloads against `Quiz_Show_Kit_SHA256SUMS.txt`. `Quiz_Show_Kit_Release_Manifest.json` identifies the exact source commit, source tree and artifact hashes.

## Included changes

Teacher/Competition mode persistence, five experience and five visual presets, independent question review, stable answer identities, editable DOCX preview/apply/rollback, safe shuffling, optional discussion, paired difficulty sequencing, alternating round starters, audited reserve replacement, selected statistics and revision reports, reveal-only evidence and option explanations, image zoom, configurable control labels, offline preflight/rehearsal, private host/audience views and portable recovery.

The supplied Chota Namu PNG is optional on welcome/About with a persistent visibility control. BioVista enables the new optional controls and has a feature guide; incompatible alternatives and authoring-only capabilities are described there. Original question meanings and scoring remain intact. Only the unscored practice question has newly checked NIST evidence and per-option explanations; the other 40 inherited cards retain their disclosed evidence gaps. Rejected and unresolved features remain excluded.

Builds use deterministic source fingerprints rather than stale Git working-tree labels. Release packaging verifies that the public example, Pages copies, DOCX binding, historical archive and artifact inventory match before publishing. Publishing is triggered only by an explicit release manifest update on main or a manual release run; existing releases and tags are never overwritten.

## Verification and limitations

The release workflow requires the regression suite, current build/validation, generated-file consistency and packaging checks before publication, then downloads and checks every uploaded asset. Earlier actual Linux Chromium checks covered full main/tie flows; the current showcase received focused offline rendering, shuffle/discussion, evidence, reserve rollback, zoom, audience, exports and resume checks. Detailed scoped records are in `docs/IMPLEMENTATION_QA.md`.

**Windows: not actually tested. macOS/Safari: not actually tested.** Physical speakers, pronunciation, extended-display hardware and projector quality still require rehearsal on the event machine. Linux browser or DOM tests are not native-platform certification.

Owned code is MIT; bundled libraries, event marks, recordings and supplied character artwork retain their separate terms. Preserve `THIRD_PARTY_NOTICES.md` and the asset notices. This release grants no broader logo or character reuse rights.
